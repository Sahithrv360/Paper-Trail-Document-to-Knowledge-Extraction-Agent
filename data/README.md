# Invoice Dataset Notes

The extraction baseline uses [`katanaml-org/invoices-donut-data-v1`](https://huggingface.co/datasets/katanaml-org/invoices-donut-data-v1). Its dataset card declares MIT licensing and reports 425 train, 50 validation, and 26 test examples (501 total), with `image` and JSON-string `ground_truth` columns. It attributes the invoice source to [*Samples of electronic invoices*](https://data.mendeley.com/datasets/tnj49gpmtz) (Kozłowski and Weichbroth, 2021), whose Mendeley Data page declares CC BY 4.0. Preserve attribution and review both licenses before redistributing downloaded images. Mendeley describes invoices as programmatically generated, with product information collected from online marketplaces.

Annotations use a `gt_parse` object with `header`, `items`, and `summary` groups. Header labels include `invoice_no`, `invoice_date`, `seller`, `client`, `seller_tax_id`, `client_tax_id`, and `iban`. Item labels include `item_desc`, `item_qty`, `item_net_price`, `item_net_worth`, `item_vat`, and `item_gross_worth`. For these labels, `item_net_price` is net unit price, `item_net_worth` is net line amount, and `item_gross_worth` is gross line amount. `item_vat` is a rate (for example, `10%`); `summary.total_vat` is an amount. The current adapter derives a line VAT amount from printed gross minus net when no line VAT amount is provided and marks that origin. Legacy `amount` remains deprecated and gross-first when normalizing these Donut labels; historical records without a source label retain unknown semantics and are never reinterpreted. Some records use a legacy `None` group. Seller and client labels combine names with address text; the adapter only separates an explicit newline and otherwise leaves the address unknown. The dataset does not separately label customer phone, email, or currency. The dataset card prose says 500 invoices while its split counts total 501; scripts record exact revisions and selected rows.

The downloaded image files and ground-truth manifests are stored under the git-ignored `data/raw/invoices-donut-data-v1/{train,validation,test}/` folders. Do not copy these examples into the live `watched/` folder. The evaluator reads a selected split locally and chooses deterministic, evenly spaced rows. Its JSON report records model revision, selected row indices, field coverage, and exact-match metrics; the companion Markdown report places extracted and expected fields side by side. The current download manifest does not record the dataset commit, so the report leaves that revision unspecified. Reports and raw files are local artifacts ignored by Git.

The baseline model is Katana ML's `invoices-donut-model-v1`, whose card says it was fine-tuned on invoices and reports 0.96 test accuracy without describing its metric or split protocol. Because it is associated with this dataset, treat this run as an initial compatibility check, not an independent generalization result. Do not fine-tune until split provenance and baseline failure cases have been reviewed.
